# Lean formalization

A Lean 4 / Mathlib formalization of Theorems A and D. Both are proved with GRH for the quadratic characters of prime conductor as their only hypothesis; the two computer searches are checked in Lean's kernel. The one input that is still assumed is the published split-prime bound used above `10^32` (see `Above.lean`), which Theorems A and D do not use.

The optional finite bridge excludes exponent seven for negative fundamental
discriminants with `10^32 ≤ |D| ≤ 2^135` under the same GRH input. Its single
64-cell row has a kernel-certified margin of at least `7.52277024130489382120`.
Build it with `lake build Exp7Lean.Rows.Bridge30000` from this directory.
[Proof and verification](../frontier/bridge30000/README.md)

Theorems A and D are fully formalized: their only hypothesis is GRH (`Final5.lean`, `Final6.lean`).

```lean
theorem theoremA_fundamental_GRH (hGRH : GRHPrimeConductor) (a b : ℤ)
    (hfund : Int.IsFundamentalDiscr (QuadraticAlgebra.discr a b))
    (hneg : QuadraticAlgebra.discr a b < 0) [IsDomain (QuadraticAlgebra ℤ a b)]
    (hlow : (QLOW : ℤ) ≤ -QuadraticAlgebra.discr a b)
    (hhi : -QuadraticAlgebra.discr a b ≤ (QTOP : ℤ)) :
    Monoid.exponent (ClassGroup (QuadraticAlgebra ℤ a b)) ≠ 7
```

```lean
theorem theoremD_fundamental_GRH (hGRH : GRHPrimeConductor) (a b : ℤ)
    (hfund : Int.IsFundamentalDiscr (QuadraticAlgebra.discr a b))
    (hneg : QuadraticAlgebra.discr a b < 0) [IsDomain (QuadraticAlgebra ℤ a b)]
    (hhi : -QuadraticAlgebra.discr a b ≤ (QTOP : ℤ)) :
    Monoid.exponent (ClassGroup (QuadraticAlgebra ℤ a b)) = 7 ↔
      ∃ q ∈ known, QuadraticAlgebra.discr a b = -(q : ℤ)
```

Here `QTOP = 10^32`, `QLOW = 3.1·10^20`, `known` is the list of 33 primes, and `GRHPrimeConductor` says that for every prime `q ≡ 3 (mod 4)` the zeros of Mathlib's `DirichletCharacter.LFunction` of the quadratic character mod `q` in the open critical strip have real part `1/2`.

`Final5.lean`, `Final6.lean` and the 866 certificate files (465 for the main search, 401 for the low range) are outside the default build target; `lake build Exp7Full` checks them (about 20 core-hours, 5 to 7 GB of memory per job).

The statements with the search hypotheses explicit are in `Final4.lean`:

```lean
theorem theoremA_rows (hGRH : GRHPrimeConductor) (hS : SearchHigh) {q : ℕ} (hq : q.Prime)
    (h4 : q % 4 = 3) (hlow : QLOW ≤ q) (hhi : q ≤ QTOP) : ¬ IsExp7 q

theorem theoremD_rows (hGRH : GRHPrimeConductor) (hS : SearchHigh) (hSL : SearchLow) {q : ℕ}
    (hq : q.Prime) (h4 : q % 4 = 3) (hhi : q ≤ QTOP) : IsExp7 q ↔ q ∈ known
```

`Fundamental.lean` states the same results without the project's ring `OK q`:

```lean
theorem theoremA_fundamental (hGRH : GRHPrimeConductor) (hS : SearchHigh) (a b : ℤ)
    (hfund : Int.IsFundamentalDiscr (QuadraticAlgebra.discr a b))
    (hneg : QuadraticAlgebra.discr a b < 0) [IsDomain (QuadraticAlgebra ℤ a b)]
    (hlow : (QLOW : ℤ) ≤ -QuadraticAlgebra.discr a b)
    (hhi : -QuadraticAlgebra.discr a b ≤ (QTOP : ℤ)) :
    Monoid.exponent (ClassGroup (QuadraticAlgebra ℤ a b)) ≠ 7
```

`GRHPrimeConductor` is the hypothesis of the theorem itself (GRH for the characters of prime conductor). The other two hypotheses are what remains to be formalized: completeness of the two searches (`SieveKernel.lean` has the packed-bitset primitives for this). `EF.explicitFormulaBound : ExplicitFormulaBound` has no hypotheses. `isExp7_of_known_all : ∀ q ∈ known, IsExp7 q` has no hypotheses.

The headline statements are in `Final.lean`, for `IsExp7 q := Monoid.exponent (ClassGroup (OK q)) = 7`, where `OK q = ℤ[ω]`, `ω² = ω − (q+1)/4`, is the ring of integers of `ℚ(√-q)`:

```lean
theorem theoremA_classGroup (C : Computed) {q : ℕ} (hq : q.Prime) (h4 : q % 4 = 3)
    (hlow : QLOW ≤ q) (hhi : q ≤ QTOP) : ¬ IsExp7 q

theorem theoremD_classGroup (C : Computed) (L : ComputedLow) {q : ℕ} (hq : q.Prime)
    (h4 : q % 4 = 3) (hhi : q ≤ QTOP) : IsExp7 q ↔ q ∈ known
```

`Step1.lean` proves `normEq_classGroup`: if the class group has exponent 7 and `p ≠ q` splits, then `4p^7 = x² + qy²` with `y ≥ 1`, and `p ∤ y` for odd `p`. The proof builds the ideal `P = (p, ω − t)`, shows `P · P̄ = (p)`, uses the exponent to get `P^7 = (α)`, and takes norms. `OK q` is shown to be a Dedekind domain from Mathlib's result that `QuadraticAlgebra ℤ a b` is the integral closure when the discriminant is fundamental.

The sections below describe the abstract versions (`theoremA`, `theoremD`, `classification`), which take the predicate `IsExp7` as a parameter and Step 1 as a hypothesis.

## What is proved

`Exp7.classification` (in `Exp7Lean/Above.lean`):

```lean
theorem classification {IsExp7 : ℕ → Prop} (H : Inputs IsExp7) (P : Published IsExp7) {q : ℕ}
    (hq : q.Prime) (h4 : q % 4 = 3) : IsExp7 q ↔ q ∈ known
```

That is: given the inputs below, a prime `q ≡ 3 (mod 4)` has class group of exponent 7 if and only if it is one of the 33 listed primes.

`Exp7.theoremD` (in `Exp7Lean/Low.lean`) proves the same equivalence for every `q ≤ 10^32` without assuming any published table:

```lean
theorem theoremD {IsExp7 : ℕ → Prop} (H : Inputs IsExp7) (L : LowInputs IsExp7) {q : ℕ}
    (hq : q.Prime) (h4 : q % 4 = 3) (hhi : q ≤ QTOP) : IsExp7 q ↔ q ∈ known
```

On the way the development proves:

- `Exp7.theoremA` (`Main.lean`): Theorem A, no exponent-7 `q` with `3.1·10^20 ≤ q ≤ 10^32`.
- `Exp7.above_bound` (`Above.lean`): `4 (1.881 log D + 6.18)^14 < D` for every real `D ≥ 10^32`, proved from Mathlib's bounds on `e` and `log 2`.
- `Exp7.not_exp7_above`: no exponent-7 `q ≥ 10^32`.

Lean checks all of the following:
- every step that connects the inputs
- the bootstrap chain from `10^32` down to `4·4297^7`, including the prime gaps it uses
- that every prime `≤ 691` is inert, and that `q ≡ 3 (mod 8)`
- the existence of the least split prime and its range `701 ≤ p ≤ 4297`
- the Jacobi-symbol conditions
- the ladder lower bounds `Qlo p`
- all the exact arithmetic

`#print axioms` shows only Lean's standard axioms, `propext`, `Classical.choice` and `Quot.sound`. The source contains no `sorry`, no `native_decide` and no added axioms.

## What is assumed (not formalized)

> This section describes the original abstract interface. Most of these inputs are now proved; see the status table at the top. The final theorems in `Final4.lean` assume only `GRHPrimeConductor`, `SearchHigh` and (for Theorem D) `SearchLow`.

These are the fields of `Inputs` and `Published`. Each is a precise statement of what the note establishes outside Lean, or imports from the literature.

| Field | Statement | Established by |
|---|---|---|
| `Inputs.normEq` | exponent 7 and `p` split ⇒ `4p^7 = x² + qy²` with `y ≥ 1` | **proved** in `Step1.lean` for the class-group predicate |
| `Inputs.cert` | each of the 51 certificate rows `⟨Q, X⟩` forces a split prime below `X` | Steps 2–3: explicit formula under GRH; rows verified by `kernel_verify.py` and `independent/verify_fixedpoint.cjs` |
| `Inputs.search` | no survivor for the 465 primes `701 ≤ p ≤ 4297` | Step 4: three independent search programs |
| `Published.ekn3` | under ERH, a split prime `p ≤ (1.881 log q + 6.18)^2` exists for `q > e^25` | Elsenhans–Klüners–Nicolae, Theorem 3 (from Bach–Sorenson) |
| `Published.ekn1` | the exponent-7 list below `3.1·10^20` | Elsenhans–Klüners–Nicolae, Theorem 1 and Table 1 (used by `classification` only) |
| `LowInputs.normEqPrim` | as `normEq`, with `p ∤ y` for odd `p` | **proved** in `Step1.lean` for the class-group predicate |
| `LowInputs.certLow` | each of the 124 extra rows forces a split prime below `X` | explicit formula under GRH; rows verified by both verifiers |
| `LowInputs.direct` | the exponent-7 list below `10^5` | `lowrange/direct.py` |
| `LowInputs.searchLow` | for `3 ≤ p < 2760` and `q < 3.1·10^20`, the only prime survivor with exponent 7 is `118843` | `lowrange/lowsearch.c` and `lowrange/classify.py` |
| `LowInputs.exp118843` | `ℚ(√-118843)` has exponent 7 | class group computation |

`Splits q p` is defined by the Dedekind–Kummer criterion: `2` splits iff `q ≡ 7 (mod 8)`, and an odd `p` splits iff the Jacobi symbol `(-q/p)` is 1. In `Main.lean`, `Above.lean` and `Low.lean`, `IsExp7` is a parameter, so those theorems hold for any predicate that satisfies the inputs; `Final.lean` instantiates it with Mathlib's `ClassGroup`. The reduction from fundamental discriminants `D` to primes `q` (Step 0, genus theory) is also not formalized.

The certificate rows in `Basic.lean` and `Low.lean` are generated from `../certificate.json` and `../lowrange/certificate_full.json`. As a check that the search hypotheses state exactly what was computed, `Qlo p` evaluated in Lean equals the lower bound in the production logs for all 465 primes, and `QloFull p` equals the lower bound in `lowrange/low_run.log` for all 401 primes.

## Next steps toward a full formalization

1. `cert`: the explicit formula for `L(s, χ)` is not in Mathlib. That is the main gap.
2. Step 0: genus theory, in the same setting as `Step1.lean`. The class-group computations (`direct`, `exp118843`) need a bound on generators of the class group.
3. `search`: about 10^15 candidates are beyond direct kernel checking. A verified sieve with a small checkable certificate would be needed.
